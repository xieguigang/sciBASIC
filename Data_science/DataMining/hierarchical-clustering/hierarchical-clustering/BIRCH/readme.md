# BIRCH 预聚类详解
## 一、BIRCH 是什么
**BIRCH**（Balanced Iterative Reducing and Clustering using Hierarchies，利用层次结构的平衡迭代归约和聚类）是 1996 年由 Zhang 等人提出的聚类算法，专门为**超大规模数据集**设计。
它的核心思想是：**不直接对原始数据点聚类，而是先用一个紧凑的树形结构（CF树）对数据做“预聚类/压缩”，把海量数据压缩成少量的“微簇”，再对微簇做最终聚类。**
---
## 二、核心数据结构
### 1. 聚类特征 CF（Clustering Feature）
CF 是 BIRCH 的灵魂。一个簇的 CF 是一个三元组：
$$CF = (N, \overrightarrow{LS}, SS)$$
- **N**：簇中数据点的个数
- **LS**（Linear Sum）：各点的线性和（向量），即 $\sum_{i=1}^{N} \vec{x}_i$
- **SS**（Square Sum）：各点的平方和（标量），即 $\sum_{i=1}^{N} \|\vec{x}_i\|^2$
**为什么强大？** CF 是**可加的**：
$$CF_1 + CF_2 = (N_1+N_2,\ LS_1+LS_2,\ SS_1+SS_2)$$
这意味着两个簇合并时，只需 O(1)（对固定维度）地合并 CF，而**不需要访问原始数据点**。由 CF 还可推导出：
| 量 | 公式 |
|---|---|
| 簇中心（质心） | $\vec{c} = LS / N$ |
| 簇半径 | $R = \sqrt{SS/N - \|LS/N\|^2}$ |
| 簇直径 | $D = \sqrt{2SS/N - 2\|LS/N\|^2}$ |
| 两簇间距离 | 可由两簇的 CF 直接计算 |
### 2. CF 树
CF 树是一棵**高度平衡的多叉树**，类似 B+ 树：
```
                 [根节点: CF1, CF2, ..., CFB]     ← 内部节点：存放子节点的CF
                /            |            \
        [非叶节点: CF...]  [CF...]      [CF...]
        /        |          \
  [叶节点: CF1, CF2, ..., CFB, prev, next]        ← 叶节点：存放微簇的CF
   ↕ 双向链表连接所有叶节点
```
- **叶节点**：每个条目（CF）代表一个“微簇”，叶节点间用双向链表连接，便于顺序扫描
- **非叶节点**：每个 CF 汇总其下所有子节点中的数据
### 3. 三个关键参数
| 参数 | 含义 |
|---|---|
| **B（branching factor）** | 每个内部节点最多容纳的子节点数 |
| **L** | 每个叶节点最多容纳的 CF 条目数 |
| **T（threshold）** | 叶节点中每个簇的**最大直径/半径**，超过就分裂——**最重要的参数**，控制“微簇粒度” |
---
## 三、CF 树的插入算法（核心流程）
对每个新数据点，自顶向下执行：
1. **下降**：从根出发，每层选择与该点**距离最近的 CF** 对应的子节点，直到叶节点
2. **测试**：找到叶节点中最近的 CF，判断合并后簇的直径是否 ≤ T
   - **是** → 吸收该点：更新 `N += 1, LS += x, SS += ‖x‖²`，并沿路径向上更新所有祖先 CF
   - **否** → 新建一个 CF 条目；若叶节点条目数超过 L，则**分裂**叶节点（选距离最远的两个 CF 作种子，其余重新分配），分裂向上传播，必要时增加树高
3. **重建（可选）**：若内存不足，可增大 T，把旧树的叶节点条目重新插入，得到更小的树
整个过程只需扫一遍数据，内存占用只与树的大小有关，与数据总量无关。
---
## 四、BIRCH 的完整四阶段
```
阶段1：扫描数据 → 构建 CF 树（预聚类，核心阶段）
阶段2：（可选）压缩 CF 树，去除离群点、合并过近的微簇
阶段3：（可选）用传统聚类算法（如层次聚合/AGNES/K-Means）
        对叶节点的微簇做全局聚类
阶段4：（可选）重复扫数据，把点分配到最近的最终簇，精修
```
**实际使用中往往只做阶段 1**——这正是“BIRCH 预聚类”的含义：用 CF 树把百万级数据压缩成几千个微簇，再交给 K-Means 等算法做最终聚类。
---
## 五、复杂度与优缺点
**复杂度：** 单遍扫描即可构建 CF 树，时间约为 **O(n)**（一次插入代价与树高有关，树高通常很小），空间取决于 CF 树大小。
**优点：**
- ✅ 天然适合**流式/在线**数据，单遍扫描，内存可控
- ✅ 不需要事先指定簇数
- ✅ 对数据顺序的敏感度相对可控（可重建）
- ✅ 作为预处理器能极大加速后续聚类
**缺点：**
- ❌ **对非球状簇效果差**（依赖直径/半径度量）
- ❌ T 参数敏感：T 太小则树庞大、T 太大则簇粗糙
- ❌ 高维数据下距离度量退化（维数灾难），通常建议先降维（如 PCA 到 10~20 维以内）
- ❌ 数据插入顺序会影响结果

## 六、sklearn 实战示例
```python
from sklearn.cluster import Birch
from sklearn.datasets import make_blobs
X, _ = make_blobs(n_samples=100000, centers=50, random_state=42)
# n_clusters=None 表示只做预聚类（阶段1），返回微簇标签
birch = Birch(
    threshold=0.5,      # 对应参数 T
    branching_factor=50, # 对应参数 B
    n_clusters=None      # None=预聚类；设为k则内置全局聚类
)
labels = birch.fit_predict(X)
print("生成的微簇数：", len(birch.subcluster_centers_))
# 常见用法：BIRCH 预聚类 → K-Means 精修
from sklearn.cluster import MiniBatchKMeans
km = MiniBatchKMeans(n_clusters=50)
final_labels = km.fit_predict(birch.subcluster_centers_)  # 对微簇中心聚类
```
> ⚠️ 注意 sklearn 实现细节：它默认以**归约后的空间**计算，`threshold` 是叶簇半径的上界，且数据会被中心化/缩放处理，实际使用时应先标准化特征。

## 七、一句话总结
> **BIRCH 用“可加的摘要统计量（CF）”把海量数据压缩成一棵内存受限的平衡树（CF 树），实现单遍扫描的线性时间预聚类，输出的微簇可再交给任意聚类算法完成全局划分——是“大数据时代的层次聚类加速器”。**

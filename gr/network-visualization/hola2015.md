# HOLA 算法详解与实现指南
这篇论文（Kieffer 等人，IEEE TVCG 2015）提出的 **HOLA（Human-like Orthogonal Layout Algorithm）** 是一个"以人为中心"设计的正交网络布局算法。下面我按照"总体思想 → 主流程 → 各步骤详解 + 伪代码 → VB.NET 工程建议"的顺序讲解。
---
## 一、算法的核心思想
### 1.1 与传统 TSM 算法的本质区别
传统正交布局（Topology-Shape-Metrics，1986 年至今仍是主流）的流程是：
```
固定平面嵌入(先最小化交叉) → 最小化折点 → 压缩面积
```
而 HOLA 的流程完全相反——**先做低应力的自由布局，再逐步"正交化"**：
| 对比项 | TSM | HOLA |
|---|---|---|
| 出发点 | 图的抽象拓扑 | 实际坐标位置（每一步都有真实布局） |
| 优化顺序 | 交叉 → 折点 → 面积 | 应力最小化贯穿始终 |
| 折点 | 一律视为坏事 | 允许故意制造"审美折点"（论文的最大发现之一） |
| 对称性 | 基本不考虑 | 通过应力布局自然呈现 |
### 1.2 三条设计原则（P1–P3）
- **P1 应力优先**：用应力最小化松开图、揭示对称性、均匀边长、保持紧凑；后续所有修改都持续考虑应力。
- **P2 机会主义编辑**：像一个"人类编辑者"一样对现有布局做增量微调（调折点、找网格对齐）。
- **P3 树特殊处理**：树状子图单独做对称布局，并且精确控制其放置位置。
### 1.3 九条美学准则（R1–R9，来自论文的用户实验）
| 编号 | 准则 | 在算法中的体现 |
|---|---|---|
| R1 | 树应放在图外围 | Step 1 剥离树 + Step 3 优先外部面放置 |
| R2 | 人会故意制造"审美折点" | Step 2b 链配置允许在**边的中间**折弯 |
| R3 | 紧凑性 | 应力目标 + 邻域应力（4b） |
| R4 | 网格状节点排列 | 节点配置（2b）+ 机会对齐（4a） |
| R5 | 对称性 | 应力布局揭示对称 + 对称树布局（3a） |
| R6 | 少交叉 | 应力布局解开缠绕 |
| R7 | 少折点 | 但与 R2 权衡 |
| R8 | 边段长度均匀 | 应力目标 |
| R9 | 低应力 | P1，贯穿全程 |

## 二、主流程伪代码
```
算法 HOLA(G) : 连通图 G = (V, E)，节点带宽高
═══════════════════════════════════════════════
// ── Step 1: 拓扑分解 ─────────────────────────
(C, trees) ← TopologicalDecompose(G)
若 G 本质上是树（核心为空或单节点）:
    直接返回 SymmetricTreeLayout(G)
// ── Step 2: 核心图布局 ───────────────────────
P ← StressMinimisation(C)          // 2a 无约束应力布局
P ← RemoveOverlaps(P)              // 2a 消除节点重叠
constraints ← NodeConfiguration(P) // 2b-1 节点配置（度≥3 的节点）
P ← ConstrainedGradientDescent(P)  //     链（度=2 节点）自由沉降
constraints ← ChainConfiguration(P)// 2b-2 链配置（含审美折点）
P ← OrthogonalRouteRemainder(P)    // 2c 残余对角边的正交路由
// ── Step 3: 树的布局与放置 ───────────────────
若 trees 非空:
    对每棵树 Ti: TreeLayouts[Ti] ← SymmetricTreeLayout(Ti)  // 3a
    Pg ← Planarise(P)                    // 3b 平面化（哑元节点）
    F ← ComputeFaces(Pg)                 //    计算面
    按包围盒周长降序遍历 trees:           // 3c
        plc ← ChooseTreePlacement(Ti, Pg, F)
        InsertTree(Ti, plc)              //    扩面 + 插入 + 投影
    P ← GradientProjection(P)            // 3d 消散累积应力
// ── Step 4: 机会性改进（NONO 原则）──────────
P ← OpportunisticAlignment(P)       // 4a 近似对齐的节点强制对齐
P ← NeighbourStressLayout(P)        // 4b 邻域应力均匀分布
若 P.宽 < P.高:                     // 4c 旋转 90°适配屏幕比例
    P ← Rotate90(P); P ← NeighbourStressLayout(P)
P ← RemoveDummyNodes(P)             // 4d 移除哑元
P ← FinalOrthogonalRoute(P)         //    最终路由（保留故意折点）
返回 P
```
**NONO 原则**（Nothing is Obviously Non-Optimal）：最后一步的目标是消除任何"一眼就能看出还能改进"的小瑕疵。

## 三、必须先实现的基础组件
### 3.1 应力函数与应力最小化（SMACOF 迭代）
应力函数（论文 P1 的核心）：
```
stress(P) = Σ_{i<j}  w_ij · ( ‖Pi − Pj‖ − d_ij )²
    其中 d_ij = 节点 i,j 的图最短路长度（BFS 计算）
         w_ij = 1 / d_ij²
```
求解推荐用 **SMACOF 主化迭代**（比朴素梯度下降收敛稳定得多），每轮对每个节点：
```
算法 StressMinimisation(G, 最大迭代, ε):
    d[,] ← AllPairsBFS(G)                // O(n·m)
    初始化位置（圆形或随机）
    重复:
        对每个节点 i:
            sumX ← 0; sumY ← 0; wSum ← 0
            对每个 j ≠ i:
                D ← max(‖Pi−Pj‖, 1e-4)   // 防除零
                w ← 1 / d[i,j]²
                sumX += w·(Pj.x + d[i,j]·(Pi.x−Pj.x)/D)
                sumY += w·(Pj.y + d[i,j]·(Pi.y−Pj.y)/D)
                wSum += w
            newX[i] ← sumX/wSum;  newY[i] ← sumY/wSum
        更新全部坐标; s ← stress(P)
    直到 |s − s_prev| < ε 或达最大迭代
```
### 3.2 约束系统与投影（IPSep-CoLa 风格，论文引用 [11]）
HOLA 的灵活性完全建立在两类一维约束上（x、y 两轴独立处理）：
- **对齐约束**：`a.x = b.x + c`（相等关系）
- **分离约束**：`a.x ≥ b.x + g`（不等关系，g 为间距）
**梯度投影法**：先按应力梯度走一步，再把结果**投影**回约束可行域。投影用"块合并"活动集法：
```
算法 Project(变量集 X, 期望位置 Z, 约束集 Cs):
    // 1. 相等约束把变量合并成"块"，块内取期望位置的加权平均
    // 2. 反复检查分离约束:
    //      若块A与块B违反 a ≥ b + g → 合并 A、B 为一个块,
    //      新块位置 = 使约束恰好满足的最小二乘解
    // 3. 直到无违反 → 各变量取其所在块的位置
```
**去重叠**（论文引用 [13]）可简化为：对 x、y 分别扫描排序，发现重叠的节点对就在位移量较小的那个轴上加分离约束，然后投影，迭代。
> ⚠️ 这个约束求解器是整个工程中**最核心、工作量最大**的基础设施，请优先实现并单独测试。

## 四、Step 1：拓扑分解（剥叶子）
**目的（R1）**：把"挂在核心上的树"剥离出来，让核心的应力布局不被树干扰，之后把树对称地放回外围。
```
算法 TopologicalDecompose(G):
    C ← G 的副本
    ρ ← 空映射                        // ρ[叶子] = 剥离时它附着的节点
    当 C 中存在度为 1 的节点:
        S ← C 中所有度为 1 的节点
        对每个 ℓ ∈ S:
            ρ[ℓ] ← ℓ 在 C 中的唯一邻居
        从 C 中删除 S 及其关联边
    若 C 为空 或 |C| = 1:             // 2-核平凡 ⇒ G 是一棵树
        返回 "整图按树处理"
    L ← ρ 的所有键                    // 全部被剥离的节点
    H ← 新图, 节点集 = L
    // 同轮被剥的节点之间互相重连:
    对每个 ℓ ∈ L:
        若 ρ[ℓ] ∈ L:  H.加边(ℓ, ρ[ℓ])
    R ← { ρ[ℓ] : ℓ ∈ L } \ L          // 核心中挂着树的节点 = 根
    对每个 r ∈ R:
        r′ ← r 的副本节点, 加入 H
        对每个 ρ[ℓ] = r 的 ℓ: H.加边(r′, ℓ)
    trees ← H 的连通分量              // 每个分量是一棵树, 根为 r′
    返回 (C, trees)
```
**正确性要点**（帮你验证实现）：
- 父指针 ρ 构成森林，每个分量恰有一个根 r′（r ∈ C 的副本），故树的棵数 = |R|；
- 树中较晚剥离的节点会成为较早剥离节点的"父"，因此 `ρ[ℓ]∈L` 的边把剥离顺序串成树；
- 剥完后 C 中所有节点度 ≥ 2（含环），这正是后续"链"定义的前提。

## 五、Step 2：核心图布局
### 5.1 节点配置（Node Configuration）
**目的（R4 网格对齐）**：对每个度 ≥ 3 的节点 v，把它的一部分邻居"吸附"到 v 的东/南/西/北四个正方向上（每个方向至多一个邻居）。
**关键规则**（论文明确给出）：
1. 按节点度**降序**处理（实验表明先配置高度数节点能获得更多总对齐数）；
2. 度 = 2 的节点称为 **link（链节）**，完全不参与此步，留给链配置；
3. 分配要**最小化总角位移**：邻居 u 当前相对 v 的角度 θu 与所指派罗盘方向角之差的和；
4. **禁止反转正交序**：若当前 u.x < v.x，则 u 不能被指派为 EAST（其余方向同理）；
5. **禁止改变邻居的循环序**：分配后的方向在圆周上的顺序必须与当前角度顺序一致。
```
算法 NodeConfiguration(P):
    constraints ← ∅
    待配置 ← { v ∈ C : deg(v) ≥ 3 }, 按度降序
    对每个 v ∈ 待配置:
        N ← v 的邻居, 按当前极角 θu = atan2 排序（保持循环序）
        A ← SolveDirectionAssignment(v, N)      // 见下
        对每个:
            EAST ⇒ constraints += [u.y = v.y] 和 [u.x ≥ v.x + gap]
            WEST ⇒ constraints += [u.y = v.y] 和 [u.x ≤ v.x − gap]
            NORTH⇒ constraints += [u.x = v.x] 和 [u.y ≤ v.y − gap]  // 屏幕坐标 y 向下
            SOUTH⇒ constraints += [u.x = v.x] 和 [u.y ≥ v.y + gap]
        Project(P, constraints)
    返回 constraints
算法 SolveDirectionAssignment(v, N):      // 规模极小，可暴力/回溯
    // 每个邻居 u 的候选方向 = 满足"不反转正交序"的罗盘方向（通常 1~2 个）
    // 回溯枚举注入式指派（方向 ≤ 4 个，每方向至多 1 邻居，允许不指派）
    // 舍弃违反"循环序一致"的分支
    // 目标: min Σ |θu − dirAngle(c)|   （角度差归一化到 [0°,180°]）
```
**随后**执行一次带约束的梯度下降（3.1 + 3.2 组合）：已配置的节点受约束约束住，而链保持自由，会"沉降"到平衡、均匀的位置，磨平投影产生的锯齿。
### 5.2 链配置——论文最有特色的部分
**链** = 核心中由度 2 节点构成的极大路径 v1…vk，其两端 v1、vk 的"另一侧邻居"记为 u、w。
**核心创新（R2）**： bends 不只放在节点上，**也允许放在边的中间**（审美折点）——用于强调对称、保证路径连续性。
```
算法 ChainConfiguration(P):
    对 C 中每条链 (v1…vk, 端邻居 u, w):
        // ① 确定两端连接方向 d0(v1 相对 u), dk(vk 相对 w)
        d0候选 ← e0 已在节点配置中对齐 ? {已定方向} 
                                           : 满足正交序的所有罗盘方向（≤2 个）
        dk候选 ← 同理
        // ② 枚举"最小折弯序列"
        best ← (cost=∞)
        对 d0 ∈ d0候选, dk ∈ dk候选:
            对 bendSeq ∈ MinimalBendSequences(u, w, d0, dk):
                cost, positions ← GreedyBendPlacement(链, d0, bendSeq)
                若 cost < best.cost: 记录
        // ③ 强制执行：把链按折点切成若干"直段"
        按 best.positions 将链的边分段
        对每段（例如水平段含节点 va..vb）:
            constraints += [va.y = va+1.y = … = vb.y]   // 垂直段则对齐 x
        段端与 u / w 之间加分离约束（保证方向关系）
        Project(P, constraints)
```
**最小折弯序列**怎么求？把它看成"给定两端连接方向的正交连接线布线"（论文引用 [36]）：
```
算法 MinimalBendSequences(u, w, d0, dk):
    // 出发朝向 h0 = d0; 到达朝向 hm = dk 的反方向
    // (例: v1 在 u 的 EAST ⇒ 出发朝向 EAST;
    //       vk 在 w 的 NORTH ⇒ 从北往南进入 w, 到达朝向 SOUTH)
    Δ ← (w.x − u.x, w.y − u.y)
    对 m = 1, 2, 3, … (通常 ≤ 4):
        对每个长度为 m 的 {L,R} 字符串:
            由 h0 逐步转 ±90° 得到朝向序列 h0..hm
            若 hm 不符 → 舍弃
            若 位移可行性检查不通过 → 舍弃
                // 检查: Δx>0 ⇒ 序列中须含 EAST 朝向; Δx<0 ⇒ 须含 WEST;
                //        Δy 同理; Δx=0 且只含单侧朝向 ⇒ 段长须全 0（注意首末段须>0）
        若存在可行序列: 返回该 m 的全部可行序列
```
**贪心选折点位置**——代价函数（论文给出）：
- **边 ei 作为折点**：代价 = f(|斜率− σ|)，σ ∈ {+1, −1} 由该折的转向决定；边越接近 45° 对角线，越适合在此折弯；
- **节点 vj 作为折点**：以 vj 中心为顶点、两条边平行于两腿的**等腰三角形，其底边的斜率**与 σ 之差（底边斜率接近 ±1 意味着两条边关于对角线对称，天然像一个"拐角"）；
- f 是递增函数（实现时取绝对值或平方即可）。
```
算法 GreedyBendPlacement(链, d0, bendSeq):
    // 候选位置沿链排列: [v1, e1, v2, e2, …, vk]，折点须按序、位置严格递增
    // 注意: 两个相邻折点之间必须留出"直段"，首段沿 d0 轴、末段沿 dk 轴
    prev ← 链起点之前
    total ← 0
    对 bendSeq 中每个折（转向 L 或 R）:
        在 prev 之后、且能给剩余折留出位置的候选中:
            选代价最小的位置 p（节点或边）
        total += cost(p);  prev ← p
    返回
```
> 📌 论文对此处的贪心细节着墨不多（"greedy process that chooses locally optimal points"），上面的直段约束与候选扫描方式是我基于论文语义给出的可操作解释。实现时你也可以给"直段内节点的对齐偏差"加权进代价，效果通常更稳。
>
> 📌 论文还提到：对**大图**，可用 ACA 算法（引用 [20]，即"把力导向布局吸附到网格"的贪心启发式）替代链配置，效果更好；小图则用上述原生方法。
### 5.3 残余对角边的正交路由（Step 2c）
正交化后大部分连线已是笔直的轴对齐线段，剩下的对角连线用正交布线器（参考 [36]，可用网格 A* 简化实现）补上。**约束**：核心中每个节点的连线必须接入其**至少两个不同的侧面**（否则该节点在 Step 3b 平面化后会退化成"叶子"，破坏面结构）。

## 六、Step 3：树的布局与放置
### 6.1 对称树布局（Manning & Atallah 算法，引用 [21]）
**目的（R5）**：树若有结构对称性，画出来就必须对称。
```
算法 SymmetricTreeLayout(T, 生长方向=SOUTH):
    // ── 自底向上计算每个节点的"子树签名"（用于同构判定）──
    Signature(v) ← Hash(排序后的 { Signature(c) : c ∈ children(v) })
    // ── 递归布局 ──
    LayoutSubtree(v):
        对 v 的每个孩子 c: LayoutSubtree(c)
        把 v 的孩子按签名配对:
            同签名孩子两两配对 → 一左一右镜像放置在过 v 的竖直轴两侧
            未配对的孩子 → 尽量靠近轴线放置（保持"近似对称"）
        v 置于轴上; 孩子所在层放在 v 下方（SOUTH 生长）
    // 层间距 = 层高; 边做正交路由, 父子连接点取朝向对方的侧面
```
### 6.2 平面化与面计算（Step 3b）
```
算法 Planarise(P):
    // 第一遍：折点→哑元节点；消除节点对之间的多重边（只留一条）
    对每条连线的每个折点 b: 在 b 处插入哑元节点并拆分该连线
    对每对节点间多余的边: 视作经由哑元的中转
    // 第二遍：扫描线检测交叉（所有线段已轴对齐，O(n log n)）
    事件 ← 所有 H/V 线段端点, 按 x 排序
    活动集维护当前穿过的水平段, 检测与垂直段的相交
    对每个交叉: 插入哑元节点, 拆分两条连线
    返回平面化图 Pg
算法 ComputeFaces(Pg):        // 标准平面图面遍历
    对每个节点: 关联半边按角度排序
    对每条未访问半边:
        顺次取 "在终点处从反向半边顺时针转到的下一条半边" 追踪
    有向面积代数和为负（或包围无穷远）者为外部面 f_ext
```
### 6.3 树放置决策——论文最精巧的工程设计
每棵树的放置是一个**四元组**：
- `f`：根节点 ri 所在的面（f ∈ F）
- `dp`：放置方向 ∈ 8 方向（N/S/E/W + NE/NW/SE/SW）
- `dg`：生长方向 ∈ 4 基数方向。**约束：dp 为基数 ⇒ dg = dp；dp 为序数 ⇒ dg ∈ dp 的两个基数分量之一**
- `b`：翻转位（树是否关于生长轴镜像）
```
算法 ChooseTreePlacement(Ti, Pg, F):
    root ← Ti 的根在核心中的对应节点 ri
    cands ← { (f, dp, dg, b) : f ∈ F 且 ri 在 f 的边界上,
                                dp ∈ 8 方向, dg 满足上述约束, b ∈ {T,F} }
    对每个 cand:
        Δstress[cand] ← TentativeInsert(Ti, cand)
            // 生成扩面分离约束（把面 f 的边界推开给树腾地方）
            // 至少尝试 x 维先扩 / y 维先扩 两种顺序
            // 投影 → 测应力增量 → 回退撤销
    // 默认配置下的字典序优先级（论文明确给出）:
    //   ① dp 为基数方向   ② f 为外部面 f_ext   ③ Δstress 最小
    返回按 (是否序数方向, 是否内部面, Δstress) 字典序最小的 cand
算法 InsertTree(Ti, (f, dp, dg, b)):
    按 把 6.1 的树布局翻转/旋转后平移到 ri 旁
    生成扩面分离约束（树的包围盒作为占位矩形加入约束系统）
    把树节点/边并入布局, Project(P)
```
树按**包围盒周长降序**依次插入。全部插完后做一次梯度投影（Step 3d），消散插入过程中累积的应力。

## 七、Step 4：机会性改进

算法 OpportunisticAlignment(P):        // 4a
    // 找"差一点点就对齐"的节点对
    对每对:
        若 0 < |u.x − v.x| ≤ ε:  试加 [u.x = v.x], 投影,
                                  若应力增量小且不产生重叠 → 保留, 否则回退
        y 方向同理（两轴都接近时选偏差较小者）

算法 Rotate90(P):                       // 4c

        方向 ← 使多数树旋转后生长方向为 SOUTH（论文的确定性规则）
        所有节点位置 → (y, −x) 或 (−y, x)   // 不旋转节点自身尺寸（标签保持水平）
        同步变换所有约束（x↔y 轴互换, 不等号相应翻转）
        NeighbourStressLayout(P)
// 4d: 移除平面化哑元节点
//     最终正交路由: 必须让边路由"穿过"链配置中故意创建的审美折点，
//     其余边可相对新节点位置重新优化

## 八、VB.NET 工程实现建议
### 8.1 主控骨架
```vb.net
Public Class HolaLayouter
    Public Function Layout(g As Graph) As LayoutResult
        Dim decomp = TopologicalDecompose(g)
        If decomp.IsWholeTree Then
            Return New LayoutResult(SymmetricTreeLayout(decomp.WholeTree, GrowthDir.South))
        End If
        Dim core = decomp.Core
        StressMajorization(core, 200, 0.001)
        RemoveOverlaps(core)
        Dim cons As New ConstraintSet()
        NodeConfiguration(core, cons)
        ConstrainedGradientDescent(core, cons)
        ChainConfiguration(core, cons)
        RouteDiagonals(core)
        If decomp.Trees.Any() Then
            Dim placements = decomp.Trees _
                .OrderByDescending(Function(t) t.BoundingBoxPerimeter)
            For Each tree In placements
                InsertTree(tree, ChooseTreePlacement(tree, core))
            Next
            GradientProjection(core, cons)
        End If
        OpportunisticAlign(core, cons, epsilon:=4.0)
        NeighbourStressLayout(core, cons)
        If WidthOf(core) < HeightOf(core) Then Rotate90(core, cons)
        RemoveDummies(core)
        FinalRoute(core, preserveAestheticBends:=True)
        Return ExtractResult(core)
    End Function
End Class
```

### 8.3 工程注意事项
1. **数值细节**：坐标用 `Double`；距离计算防除零；`Math.Atan2` 注意象限；开启 `Option Strict On`。
2. **坐标系**：VB.NET GDI 绘图 y 向下，NORTH 对应 y 减小——伪代码中所有方向判断要统一约定后再写。
3. **性能**：论文 Fig.8 显示 10–170 节点、密度 1.1–1.5 时 HOLA 最长约 3 分钟（当时部分为 Python 实现），小图 9–97ms。你的目标场景（几百节点以内、低密度）用 VB 完全可行；全对最短路 O(n·m) 是主要热点，n 大时可只取 k 近邻近似。
4. **断连图**：论文假设连通图。实际系统应先按连通分量分组，逐个布局后打包排列。
5. **可调参数**：节点间距 gap、对齐阈值 ε、期望边长 L、应力收敛 ε——建议集中到一个 `HolaOptions` 类。
6. **重要参考**：论文结尾说明 HOLA 已并入开源库 **Adaptagrams**（C++，adaptagrams.org），包含约束求解、正交路由等组件——这是与论文最接近的参考实现，逻辑可直接对照移植到 VB.NET。

## 九、一句话总结
HOLA 的本质是：**先剥树 → 对核心做"应力布局 + 贪心正交化（允许审美折点）" → 对称地放树（优先外围、优先正方向）→ 最后像人一样修修补补**。整个算法建立在"应力最小化 + 约束投影"这套基础设施上，建议你把 80% 的前期精力投入在 SMACOF 和一维约束求解器上，其余步骤都是在这套地基上的组合应用。
